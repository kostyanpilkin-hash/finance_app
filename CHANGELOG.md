# Журнал изменений

## 2026-11-12

### «Кто потратил» (схема v5)
- У расхода появилось поле `spent_by_user_id` — кто именно потратил деньги, отдельно от автора записи (`created_by_user_id`). Миграция v5 разово заполняет его автором; в `transaction_upsert` для расхода значение валидируется (пользователь должен существовать и не быть удалён), по умолчанию подставляется автор, для дохода и перевода поле принудительно NULL. Поднятие `SCHEMA_VERSION` до 5 штатно требует обновления всех устройств до синхронизации.
- Форма операции: селект «Кто потратил» показывается только для расхода, по умолчанию — текущий пользователь устройства (при редактировании — сохранённый спендер или автор). В списке операций у расхода показывается спендер; если он не автор — «Мария (внёс Иван)» (`ui.enteredBy`).
- Аналитика «Расходы по людям» (дашборд и аналитика) группирует по `spentByUserId` с откатом на автора; «Доходы по людям» по-прежнему по автору. В списке операций джойнится имя спендера (`suName`).
- Бот: новый шаг «Чья трата?» для расхода между категорией и датой — инлайн-кнопки пользователей с отметкой автора «✓»; дефолт — привязанный пользователь. В «Изменить» у расхода есть кнопка смены спендера; в деталях операции строка «Кто потратил» выводится, когда спендер отличается от автора.
- Отчёты: в PDF-таблице и в xlsx-экспорте отдельные колонки «Автор» и «Кто потратил» (у не-расходов пусто).

### Кликабельные диаграммы по категориям
- `DonutChart` научился `onSelect`: клик по сектору или строке легенды отдаёт исходные элементы среза. Диаграммы «по категориям» на дашборде (расходы и доходы) и в аналитике открывают окно со списком операций (только просмотр: дата, комментарий, сумма; закрытие по Esc и клику по фону, `aria-modal` — новый `Dialog` + `CategoryTxDialog`).
- «Без категории» и хвост «Остальное» кликабельны: `TransactionFilter.category_ids` фильтрует по списку категорий (`IN`), а пустой элемент списка добавляет `OR category_id IS NULL`. Срезы несут `members` — дедуп по имени и сливаемый хвост сохраняют все исходные категории.

### Тесты
- `finance-storage`: бэкфилл спендера миграцией v5, дефолт/валидация/очистка спендера в `transaction_upsert`, фильтр `category_ids` с NULL-членом и джойн `suName`.

### «Чья операция» у всех типов (схема v6)
- Поле `spent_by_user_id` распространено на доходы и переводы: в `transaction_upsert` оно валидируется и по умолчанию равно автору для всех видов; принудительный NULL убран. Миграция v6 разово добивает NULL-строки автором и поднимает `SCHEMA_VERSION` до 6 — старые клиенты обязаны обновиться до синхронизации (иначе бы затирали поле при редактировании).
- Форма операции: селект владельца показывается для всех типов с подписями «Кто потратил» / «Кто получил» (`ui.receivedBy`) / «Чья операция» (`ui.whoseOp`); дефолт — вносящий.
- Список операций: справа под суммой всегда три строки — «Время: …» (+🤖), «Внёс: …», и подпись владельца по типу («Кто потратил» / «Кто получил» / «Чья операция»). Ключи `ui.time`, `ui.entered`; `ui.enteredBy` удалён.
- Аналитика «по людям» и для расходов, и для доходов группируется по `spentByUserId ?? createdByUserId` (`suName ?? uName`); переводы не участвуют.
- Бот: шаг выбора владельца у всех видов — после категории (расход/доход) или после счёта назначения и суммы зачисления (перевод), всегда перед датой; промпты «Чья трата?» / «Кто получил?» / «Чья операция?» (`receiver_pick`, `whose_pick`). У всех видов теперь 10 шагов; в «Изменить» кнопка смены владельца есть у всех типов; в деталях операции «Автор» и «чья операция» показываются всегда двумя строками.
- Отчёты: колонка «Кто потратил» в PDF-таблице и xlsx переименована в «Чья операция» и заполняется для всех типов. В журнале `journal.field.spentByUserId` локализовано как «Чья операция» — видны и владелец, и автор изменения.

### Окно «Что нового»
- После обновления приложение при запуске показывает модальное окно с новинками версии: заголовок «Что нового в X.Y.Z», список пунктов и кнопка «Понятно»; любое закрытие (кнопка, Esc, клик по фону) помечает версию просмотренной — локальная настройка `settings.whatsnew_seen`, каждое устройство показывает окно один раз.
- Тексты новинок — `src/lib/whatsnew.ts`: по версии и на трёх языках, заполняется при каждом релизе вместе с CHANGELOG; если для версии записи нет — показывается заглушка «Техническое обновление».
- При чистой установке и присоединении к хосту окно не показывается: версия помечается просмотренной при завершении онбординга. Повторно открыть окно можно кнопкой «Что нового» в разделе «О программе» настроек.

### Тесты
- `finance-storage`: бэкфилл владельца (v6, `SCHEMA_VERSION >= 6`), хранение и дефолт владельца у дохода и перевода в `transaction_upsert`.

- Подпись владельца по виду операции вынесена в общие хелперы: `whose_key()` (бот) и `ownerLabelKey()`/`ownerOf()` (`src/lib/owners.ts`, фронт) — каскад `kind → label` и группировка по владельцу больше не дублируются.
- Актуализированы устаревшие doc-комментарии к `spent_by_user_id` (поле теперь у всех видов, а не только у расхода).

## 0.1.8 — 2026-11-12

### Сохранность данных
- Запись строк синхронизации заменена на UPSERT (`ON CONFLICT(id) DO UPDATE`): старые клиенты больше не затирают новые колонки (`accounts.bank`, `payment_system`, `goals.account_id`) — незаданные поля сохраняют значения, явный `null` очищает.
- Версия схемы (`SCHEMA_VERSION`) в рукопожатии: `/hello` отдаёт её, `/push` отвергает клиентов с другой схемой кодом 409 `client_outdated`/`host_outdated`; клиент запоминает последнюю ошибку и показывает локализованное пояснение в настройках и при подключении в онбординге.
- Восстановление из копии стало отложенным: копия проверяется (ключ, целостность, checkpoint) и кладётся рядом как `finance.db.restore`; на старте текущая база сохраняется как `backups/pre-restore-*` и подменяется подготовленным файлом, после чего приложение перезапускается. Авто-очистка трогает только `backup-*.db`.
- `device_token` переехал из таблицы `settings` в системный keyring; при старте выполняется миграция старого значения (с сохранением строки при неудаче).
- Ошибка открытия базы больше не паникует приложение: пишется `logs/startup.log`, поднимается трей и показывается экран с копиями, папкой данных, вводом ключа и перезапуском. Добавлены ErrorBoundary (всё приложение + каждый раздел отдельно) и безопасный разбор `afterJson` в журнале.

### Безопасность сети
- Подключение устройств стало двухфазным: код лишь открывает заявку, токен выдаётся только после нажатия «Разрешить» на хосте (модальное окно с именем, платформой, IP и пользователем). Заявки живут в памяти и истекают через 3 минуты.
- Защита от перебора кода: 5 неверных попыток блокируют `/pair` (429 `pairing_locked`) и сжигают все активные коды; новый код снимает блокировку. Код одноразовый, `/pair` проверяет `schemaVersion`.
- API больше не слушает `0.0.0.0`: слушатели поднимаются только на RFC1918-адресах машины и перечитываются каждые 30 секунд; middleware отклоняет не-LAN адреса (публичные, CGNAT) ответом 403 `not_lan`.
- Asset-протокол сужен до `$APPDATA/attachments/**` с явным запретом базы, копий и логов; `attachment_path` принимает только 64-символьный hex-хеш.

### Форма операции и оптимизация ввода
- При редактировании операции теперь подставляются сумма (в т.ч. исходная сумма в валюте) и её исходная дата вместо «сегодня»; при смене даты время операции сохраняется, а не сбрасывается на текущее. То же при предзаполнении из напоминания («Внести»).
- Форма обёрнута в `<form>`: сохранение по `Enter`, отмена по `Esc`. Валидация на клиенте (сумма > 0, счёт, категория, счёт назначения у перевода) подсвечивает поля и пишет понятное сообщение; сырые ошибки бэкенда мапятся в локализованные (`ui.err.*`) на трёх языках.
- Поиск по истории операций дебаунсится на ~250 мс — запрос не уходит на каждый символ (`useDebounced`).
- Подсказка «≈ по курсу НБРБ» считается локально по уже загруженным курсам (`convertMinorLocal`, округление до копеек) — без вызова `convert_at` на каждую цифру.
- Фото чека уходит бинарным телом `Uint8Array` с метаданными в заголовках запроса вместо конкатенации строк и `btoa`; лимит 15 МБ проверяется в форме и в команде `attachment_add`, имя файла передаётся percent-encoded. Зависимость `base64` удалена.

### Отзывчивость и скорость бэкенда
- Все команды Tauri, которые трогают БД, файлы или сеть, стали `async`: блокирующая работа выполняется на `spawn_blocking`, IPC-поток и окно больше не ждут. В частности: `discover_hosts` (mDNS-поиск ~2,5 с), `backup_create`/`auto_backup` (`VACUUM INTO`), `export_xlsx`, `unlock_db`, `attachment_add`, `pairing_decide`, `device_pair_code` — раньше любой из них мог заморозить интерфейс.
- Соединения с базой разделены: `conn` — единственная точка записи, `read_conn` (WAL) — все чтения. Запросы интерфейса (`transaction_list`, `dashboard`, `journal`, `entity_list`, `get_settings`, `rates_latest` и др.) и `/pull` API идут через `read_conn` и не встают в очередь за синхронизацией, ботом или бэкапом; чтения бота и sync переведены туда же. Для тестовых БД in-memory — именованный shared-cache, чтобы `Db` в одном процессе не видели чужие таблицы.
- Подготовленные запросы кэшируются (`prepare_cached`) во всех горячих местах `repos` и циклах синхронизации; snake_case → camelCase имена колонок мемоизированы — повторная сборка имён на каждую строку убрана.
- Один общий `reqwest::Client` на процесс (`net::client()`) для синхронизации, бота и курсов НБРБ — переиспользуются пул соединений и DNS-кэш; таймауты задаются на запросе, `connect_timeout` — 10 с. `rates_refresh` грузит валюты параллельно и пишет их одним пакетом.
- «Сегодня» в планировщике курсов и в `reminders_due` считается по локальному времени пользователя (`Local`) вместо UTC. Конвертация валют на бэкенде (`convert_with`) округляет до копеек математически (half away from zero) вместо отбрасывания — как и локальный расчёт формы.

- Кнопки (`components/ui/button.tsx`): стандартные высоты 36 px (`sm`), 40 px (`default`) и 40×40 (`icon`); для плотных строк — `icon-sm` 32 px с кликабельной зоной ≥36 px через псевдоэлемент. `hover:opacity` заменён на плавное затемнение (`brightness-95/90`), добавлены `cursor-pointer`, `active:scale-[.98]`, внешний фокус-ринг `ring-2` с `ring-offset-2`; у `disabled` реакции отключены. Свойство `loading` рисует спиннер и блокирует повторные клики — задействовано на «Создать копию», «Обновить курсы», «Найти хост» и сохранении операции.
- Единые поля: новые `Input`, `Select`, `Field`, `Checkbox`, `Segmented`, `ColorSwatches` в `components/ui` — высота 40 px, подписи над полями вместо исчезающих плейсхолдеров, одинаковый фокус-ринг и состояние `invalid` (красная рамка + `aria-invalid`). Применены во всех формах: операции, счета, категории, цели, напоминания, настройки (токен бота, подключение к хосту, PIN), онбординг, PIN/PIN-восстановление. Чекбоксы — 20 px в кликабельной строке 36 px.
- Выбор цвета категории/счёта/цели переведён с системного `<input type="color">` на палитру `CATEGORY_COLORS` (`ColorSwatches`). Переключатель периода приведён к единому `Segmented` на дашборде и в аналитике.
- Контрастность: во все 29 тем добавлен `--border-strong` (токен `field-border`) — рамки полей ≥ 3:1 к фону; подтянуты `muted-fg`, `primary`, `destructive`, `income`, `expense` до ≥ 4,5:1 (аудит скриптом по каждой теме). Тема `notion` пересобрана на контрастной палитре. Всем темам прописан `color-scheme: light/dark` для системных контролов (скроллбары, дата-пикеры).
- Типографика: `tabular-nums` для всех цифр глобально; единый типографский минус `−`; `formatMinor` локализован через `Intl.NumberFormat` (ru/be — неразрывные пробелы и запятая, en — точка), `parseMinor` понимает оба разделителя и знаки `-`/`−`; даты форматируются через `toLocaleString/toLocaleDateString(i18n.language)`. Минимальный размер шрифта поднят до 12 px (карточки счетов, календарь, легенды диаграмм).

### Сжатие размера и очистка зависимостей
- В `[profile.release]` включены `lto`, `codegen-units = 1`, `opt-level = "s"`, `strip` — исполняемый файл ужался с 24,4 МБ до **17,3 МБ (−29%)**.
- Убраны неиспользуемые зависимости: `chrono-tz` (core/storage), `tower-http` и `thiserror` (api), `dirs`/`finance-core`/`finance-bot` (src-tauri); пустой пакет `crates/bot` удалён из workspace. `thiserror` остался в core/storage — там он реально используется.
- `reqwest` выровнен до единственной 0.13 (была пара 0.12 + 0.13 у updater'а), `rust_xlsxwriter` 0.80 → 0.102 — теперь один `zip` 9.3 на всё дерево вместо 2.6 + 9.3.
- Под macOS SQLCipher собирается через `bundled-sqlcipher` и линкует CommonCrypto; OpenSSL собирается из исходников только под Windows/Linux.
- Шрифты: Outfit/Figtree/Mona Sans/Lato заменены на кириллические Manrope/Onest/Golos Text; в бандл входят только `.woff2` сабсетов `latin` + `cyrillic` (8 гарнитур × 2 файла = 433 КБ вместо ~60 файлов с vietnamese/greek/latin-ext/math и .woff-фолбэками). Сами `@font-face` собраны в `fonts.css` вручную с `unicode-range`.
- Переводы i18next грузятся лениво: локали ru/be/en — отдельные чанки, в основной бандл входит только активный язык (`loadLanguage` в `settingsStore`).
- CSS: вычищены мёртвые стили от проекта-донора (`[data-item-avatar]`, `[data-item-card]` — squircle-аватары, play-кнопка, grab-handle); убрано глобальное `content-visibility: auto`, из-за которого обрезались выпадающие списки и ломалась прокрутка.

### Этап 1/2 — базовый интерфейс
- Дашборд: расходы/доходы за месяц по валютам, плитки счетов с балансом.
- Операции: список с поиском по комментарию, добавление/редактирование расхода, дохода и перевода (с ручной суммой зачисления для разных валют), удаление.
- Счета: создание и редактирование (тип, последние 4 цифры, валюта, владелец, цвет, «в общий баланс»), архив и восстановление.
- Категории: вкладки расходы/доходы, создание/редактирование (имя, иконка, цвет), удаление с переносом операций в другую категорию.
- Журнал: лента изменений «было → стало» по полям, восстановление удалённых записей.
- Переводы ru/be/en для всех новых строк и базовых категорий.

### Этап 1 — ядро данных (часть 1)
- `crates/storage`: SQLCipher-база (файл шифруется целиком, ключ в хранилище ОС), миграции, все таблицы из плана (счета, категории, операции, вложения, цели, напоминания, курсы, audit_log, outbox/conflicts, telegram-*).
- Единая точка записи `apply_change()`: версии, seq на хосте, очередь на клиенте, подробный журнал изменений «было → стало» по каждому полю.
- Репозитории: пользователи, счета (карта с 4 цифрами, наличные, сбережения), категории (базовый набор, удаление с переносом в «Прочее»), операции (расход, доход, перевод между валютами с ручной суммой зачисления), вложения, цели, журнал с фильтрами, восстановление удалённого.
- Балансы по счетам и общий баланс с пересчётом в выбранную валюту по курсу НБРБ; клиент api.nbrb.by (BYN/USD/EUR/…).
- Ключ восстановления: base32-формат, показывается в мастере первого запуска.
- Мастер первого запуска: язык → пользователи → стартовые счета → ключ восстановления.
- Тесты: деньги, периоды (неделя с пн, границы месяцев), балансы и переводы, журнал, перенос категорий, шифрование (без ключа файл не читается).
- Примечание: для сборки SQLCipher на Windows нужен Perl — используется портативный Strawberry Perl в `tools\strawberry-perl` (без админских прав).
