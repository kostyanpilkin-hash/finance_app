# Журнал изменений

## 2026-11-02

### Этап 5 — LAN (продолжение)
- mDNS: хост анонсирует `_finance._tcp`, клиент находит его кнопкой «Найти хост» (или вводит URL вручную).
- Конфликты: хост кладёт их в `conflicts`, клиент получает в `/pull`; окно «Вариант А / Вариант Б» в настройках; `/resolve` применяет выбранную версию.
- Файл: `src-tauri/src/sync.rs`, `crates/api/src/lib.rs`, секция в SettingsPage.

### Этап 5 — LAN хост/клиент (часть 1)
- `crates/api` (axum, порт 45322): `/api/v1/hello`, `/pair` (6-значный код → токен устройства), `/push` (очередь с проверкой base_version; конфликт → таблица conflicts), `/pull?since=seq`.
- Клиент: фоновая задача — push outbox → pull изменений → применение; локально-грязные записи не затираются.
- Настройки: секция «Устройства и синхронизация» — код для пары на хосте, подключение клиента по URL+код, статус (устройств, в очереди, last_seq).

### Этап 4 — Telegram-бот (доделки)
- Выбор даты кнопками: «Сегодня / Вчера / Другая дата» (ввод ДД.ММ.ГГГГ) для расходов, доходов и переводов.
- Фото чека: после комментария бот ждёт фото (или «-»); файл скачивается через getFile и кладётся в attachments с привязкой к операции.

### Этап 4 — Telegram-бот (часть 1)
- Токен бота хранится в системном хранилище ОС (keyring); настройка в «Настройки → Telegram-бот».
- Привязка: 6-значный код (10 минут) по пользователю; бот связывает чат с пользователем.
- Пошаговый ввод кнопками: вид (расход/доход/перевод) → сумма → счёт → категория; перевод между валютами спрашивает зачисляемую сумму; комментарий последним шагом.
- Сводки /today /week /month, /balance, /undo (последняя запись бота за 10 минут).
- Запасной формат одной строкой: «-500 продукты молоко», «+1000 зп» — бот попросит только счёт и категорию.
- Ответы бота на языке пользователя (ru/be/en).

### Этап 2/3 — аналитика и курсы (продолжение)
- Аналитика: периоды день/неделя (с пн)/месяц/произвольный, столбики расходов и доходов по дням, итог и сравнение с прошлым периодом в процентах.
- Курсы НБРБ: автоматическое обновление раз в сутки (фоновый планировщик), кнопка «Обновить курсы» и список курсов в настройках.
- Фото чеков: миниатюры в списке операций.

### Этап 2 — UI (продолжение)
- Дашборд: общий баланс в BYN по последним курсам, круговая диаграмма расходов по категориям за месяц (recharts).
- Операции: фильтры по счёту и категории, группировка списка по дням, прикрепление фото чека (файлы в `attachments/`, показ через asset protocol).
- Команда `rates_refresh`: обновление курсов НБРБ для всех валют счетов + USD/EUR.

### Этап 1/2 — базовый интерфейс
- Дашборд: расходы/доходы за месяц по валютам, плитки счетов с балансом.
- Операции: список с поиском по комментарию, добавление/редактирование расхода, дохода и перевода (с ручной суммой зачисления для разных валют), удаление.
- Счета: создание и редактирование (тип, последние 4 цифры, валюта, владелец, цвет, «в общий баланс»), архив и восстановление.
- Категории: вкладки расходы/доходы, создание/редактирование (имя, иконка, цвет), удаление с переносом операций в другую категорию.
- Журнал: лента изменений «было → стало» по полям, восстановление удалённых записей.
- Переводы ru/be/en для всех новых строк и базовых категорий.

### Этап 1 — ядро данных (часть 1)
- `crates/storage`: SQLCipher-база (файл шифруется целиком, ключ в хранилище ОС), миграции, все таблицы из плана (счета, категории, операции, вложения, цели, напоминания, курсы, audit_log, outbox/conflicts, telegram-*).
- Единая точка записи `apply_change()`: версии, seq на хосте, очередь на клиенте, подробный журнал изменений «было → стало» по каждому полю.
- Репозитории: пользователи, счета (карта с 4 цифрами, наличные, сбережения), категории (базовый набор, удаление с переносом в «Прочее»), операции (расход, доход, перевод между валютами с ручной суммой зачисления), вложения, цели, журнал с фильтрами, восстановление удалённого.
- Балансы по счетам и общий баланс с пересчётом в выбранную валюту по курсу НБРБ; клиент api.nbrb.by (BYN/USD/EUR/…).
- Ключ восстановления: base32-формат, показывается в мастере первого запуска.
- Мастер первого запуска: язык → пользователи → стартовые счета → ключ восстановления.
- Тесты: деньги, периоды (неделя с пн, границы месяцев), балансы и переводы, журнал, перенос категорий, шифрование (без ключа файл не читается).
- Примечание: для сборки SQLCipher на Windows нужен Perl — используется портативный Strawberry Perl в `tools\strawberry-perl` (без админских прав).

### Этап 0 — каркас проекта
- Cargo workspace: `crates/core` (деньги и валюты с тестами), заготовки `crates/storage`, `crates/api`, `crates/bot`, десктоп-оболочка `src-tauri` на Tauri 2.
- Интерфейс: React 19 + TypeScript + Tailwind 4, боковое меню со всеми разделами (пока заглушки), горячие клавиши Ctrl/Cmd+1…9.
- Темы оформления из TutorApp (28 шт.) плюс фирменная «Изумруд» по умолчанию; языки: русский, беларуский, английский.
- Трей (открыть/выход, локализуется), закрытие окна сворачивает в трей, защита от второго запуска, автозапуск со стартом в трей.
- Иконка «зелёный кошелёк» (`scripts/generate-icon.py`).
- Установщики Windows: MSI (язык ru-RU — иначе WiX не принимает кириллическое имя «Финансы») и NSIS (русский/английский).
- GitHub Actions: проверки на каждый push (Windows) и сборка релизов Windows + macOS universal с публикацией в `finance_app_public`.
